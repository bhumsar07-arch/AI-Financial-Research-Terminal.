# RAG Evaluation

The evaluation runner calls the same Qdrant retrieval and LangChain Gemini generation path used by the FastAPI service. Ragas scores answer quality; the runner also records retrieval time, generation time, and a simple citation source-title check.

## Run the benchmark

From `rag-service`, configure PostgreSQL, Qdrant, and `GEMINI_API_KEY`, ingest the benchmark source documents, then run:

```powershell
python -m app.evaluation.runner
```

The runner uses the curated questions in `app/evaluation/benchmark.json` and writes timestamped CSV and JSON reports under `rag-service/reports/`. Scores are generated by an actual run; there are no prefilled sample scores presented as measured results.

## Metrics

| Measure | What it checks |
| --- | --- |
| Context precision | Whether relevant retrieved chunks rank near the top |
| Context recall | Whether the retrieved evidence supports the reference answer |
| Faithfulness | Whether the generated answer is supported by retrieved evidence |
| Factual correctness | Whether the answer matches the reference answer |
| Citation source match | Whether a returned source title contains the expected source label |
| Retrieval and generation latency | Average and p95 time for each stage |

Citation source match is a basic title check, not a semantic verification of every claim. Review citations manually when making quality claims.

## Dataset maintenance

Add questions only when the expected answer can be checked against a source filing or transcript. Include a concise reference answer and a source label. Evaluate qualitative document questions here; numeric financial metrics remain in the deterministic PostgreSQL financial service.
